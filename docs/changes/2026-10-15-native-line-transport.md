# LINEで送迎担当の変更を確定する

本番の会話で、「今日の送りは私に変更してください」に画面リンクを返した後、「確認した済みです」に「了解！」とだけ返していた。担当は変更されておらず、前の修正ではLINEの確認から保存までの経路が不足していた。

新しい送迎担当変更は実作業とrevisionを読み、サーバー側に15分間の確認内容を保持する。LINEには対象日・実時刻・作業・現在担当と変更後担当・今回だけの適用範囲を表示する。「2人で調整済み・変更する」で正規の担当変更を実行し、成功後にだけ変更済みと返す。短い確認の報告には同じ最終確認を返し、発言だけで変更したことにはしない。

確認内容は送信者・世帯・実作業・希望担当・revisionに固定する。二重押し、期限切れ、別の担当変更、別人による操作を区別する。無関係な会話に移った後の「確認済み」を、前の担当変更の同意には使わない。一般依頼の旧カードには従来の送信防止を残す。自分の担当のお迎えを相手へお願いする既存経路も維持する。

`private.line_transport_assignment_previews` は短命の確認情報であり、家庭データのバックアップ対象には加えない。復旧後は新しく確認し直す。確定後の担当・作業イベント・関連roleは既存の正規コマンドへ保存するため、既存の復旧対象に含まれる。

実家庭の担当を開発者が書き換えることや、テストのために実際の家族へLINEを送ることは行わない。保存までの再現は隔離したDBと外部送信を置き換えたHTTPテストで検証する。
