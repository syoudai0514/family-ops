# 確定済み入力の後の新しい用件と、送り担当の変更

前の用事を登録した後に「明日の送りは私に変更してください」と送ると、前の用事の「登録済みです」が返り続けていた。AIと定型処理の両方で、確定済みの用事を新しい文章の編集対象にしていたため。

新しい対象が書かれた用件は、前の確定済み入力から切り離して扱う。「さっきの用事の時間を変更」のような明示した参照は残し、過去の入力を勝手に複製しない。

送り担当の変更は普通のお願いにすると、ママ側に「送り担当をパパに変更」というToDoが増えるだけで、実際の送り担当が変わらなかった。今回の文は、実際の送り予定を読み、日付・時刻・現在ママから希望パパ・今回だけと表示する。「担当を調整」リンクを開くと、その日の送りの担当変更欄が開き、希望担当が選択される。

- 話し合い済みなら「すでに話し合い済みなので、そのまま担当を変更」を選んで確定する。正規の担当変更処理で、対象日と連動する未保護の家事を再解決する。
- 相手担当を自分へ変える際、未調整なら先に相手と調整する。リンクを開くだけで合意したことにせず、自分宛ての依頼は送らない。
- 自分担当のお迎えを相手にお願いする、既存のLINE内の担当変更依頼は維持する。
- 以前の誤った一般依頼カードの「この内容で送る」を押しても、そのまま送信せず、正しい担当調整の案内を返す。

今回の調査・修正で、実家庭の送り担当や依頼を開発者側から変更してはいない。実LINE送信による試験も行わない。
