# 父へのお迎え変更が新しい予定になる問題を修正

「11/5の迎えを父に変更して。合意済みです。」が一般予定として扱われ、繰り返した入力では2025年11月5日に誤登録された。予定を確認した後の「だからパパに変えてって言ったじゃん」も別の一般予定になり、実際のお迎え担当はママのままだった。

家族の呼び方と文末の合意報告を送迎担当変更として解釈する。省略した訂正は、直近の本人の発言に明示された日付・送迎を参照し、同日の予定確認を挟んでも対象を保つ。別件や別日に移った場合は確認し直す。AIのタイトル・年月日から担当変更の対象を決めない。

単独下書き・fallback・複数候補の登録前とLINE/PWAの確定時に、送迎担当変更を一般予定として登録しない検査を行う。一般予定の日付も元の発言と送信日時で補正し、AIが誤った年を付けた場合にそのまま保存しない。複数候補の原文が本人の入力にない場合は、本人の入力へ戻して検査する。

運用修復では、元の「合意済みです」と誤登録結果の対応を検証したうえで、11/5 18:20のお迎えを既存コマンドでパパへ変更し、誤登録2件を取り消した。送りはママのまま。Google同期でも取消2件は削除済み、送迎予定は同期済みと確認した。修復処理は4件の作業を固定して同一transactionで実行し、成功後の再実行は何も変更しない。

DB schema・Web画面の変更なし。既存の画像関連HTTPテスト2ファイルでは、fetch引数の型指定だけを追加し、現在のDeno/TypeScriptでも全体検証を行えるようにした。画像処理の実行時コードは変更しない。
