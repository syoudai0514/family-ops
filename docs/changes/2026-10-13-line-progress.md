# LINEの担当表示と、途中・補完作業の記録

2026-10-13 の利用者指摘①LINEの日本語と担当表示、②未実施の前段を別の人が補う、③一部済みの保育園準備を引き継ぐ、への対応。

## 表示

- 曜日限定・追加の用事は「⭐ 今日、忘れずに」。毎週の仕事を一度きりの「今日だけ」と呼ばない。
- 共有の仕事は「先に家を出る人」と「2人で分担（誰でもOK）」に分ける。食洗機を空ける担当条件と anyone の記録方式は維持し、行ごとの「誰でもOK」を重ねない。対応中の人がいれば、その人を表示する。
- コドモンは「2人分の入力がそろってから」と明記する。
- 「明日の予定・作業」は実施日を表示する。そこで翌日の保育園準備を案内する際は、準備する対象の日を別に表示する。過去日の準備も絶対日付にする。
- 長いLINE一覧はAPIの1メッセージ5,000文字・最大5件の枠で分ける。枠を超える場合は省略を説明し、詳細へのリンクを残す。

## 食洗機の例

作業カードの `••• → 状況・引き継ぎを記録` を開く。元の対象日は変えず、今日確認・実施した内容を入力する。

| 入力 | 例 |
| --- | --- |
| 見つけた状況 | 昨日の分がまだ洗えていなかった |
| 自分が行ったこと | 朝の食器を追加して洗浄を開始した |
| 今の状態・残り | 洗浄中。食器の取り出しはまだ |
| 次の作業への影響 | 洗浄が終わってから食器を取り出してほしい |

保存だけなら状況メモを残す。家族に伝える場合だけ「家族に引き継ぎを送る」を選ぶ。通常の期間は今日中、指定期限や手動で終えるまでにもできる。返答が必要なら「確認の返答が必要」を選び、相手はLINEの「共有確認」またはPWAで確認する。状況が変わったら「この共有を終える」。確認は作業の完了と別。

保存した内容は履歴の「状況・補完の記録」でも読み返せる。「見つけた状況」「行ったこと」「今の状態・残り」「次の作業へ」と記録した人を表示する。準備済みを見つけた記録は「準備済みを確認（実施者不明）」と表示し、確認者の実施とは区別する。

保存後の作業一覧には「状況メモあり · 保存した内容を見る」が出る。作業がまだ完了していなければ「作業は未完了」と表示する。開くと保存済みメモを展開して表示し、その下の空欄は「新しく追記する」ための入力欄。家族への送信を選ばなかった記録には「状況メモとして保存（引き継ぎの送信なし）」と表示する。作業そのものが済んだ場合は別途「完了」を押す。

洗浄開始を「食洗機を空ける」の完了にしない。昨日の洗浄を完了として記録する場合も、その作業の実際の完了条件を満たしたことを確認してから記録する。観察した未実施と、未入力なだけの状態を混同しない。

## 一部済みの保育園準備

チェック項目を開くと、個別の自分／相手／「済んでいた（実施者不明）」を選べる。済み項目には実施者と記録日時を表示し、後の人が残りを完了しても先の記録を変更しない。実施者が不明なら確認者を実施者にしない。

現在の保育園準備の定例は「将生」「詩乃」の2項目。子どもの準備が一部しか済んでいない場合は、その子のチェックを先に付けず、状況メモに「準備済みの物」「自分が追加で用意した物」「残っている物」を具体的に残す。シーツや着替えの内訳が分からないときは推測しない。持ち物ごとのチェックへ変更する場合は既存の定例編集で項目を分けられるが、未確認の内訳を自動で追加しない。

部分的な実施者の選択と、残りをまとめて実施する人の選択は分離した。「残りを自分がやった」は自分の実施を記録し、予定担当を変えない。済み項目への再送は実施者・時刻を上書きしない。取り消しはrevisionを確認し、相手の後の記録を消さない。

## 検証と反映

SQLで複数人の記録、不明実施者、再送、競合、世帯・テスト境界、期限、失敗時の全体rollbackを検証する。Webは個別・残り完了・補完メモ・共有・期限・通信結果不明時の同一操作再送を検証。スマホ幅の実ブラウザでは記録だけ保存、明示した引き継ぎ、履歴の再表示を確認する。架空の家庭データを使用し、家庭への実際のLINE送信や曖昧な準備状況の実記録は行わない。

反映順はDB、Edge Functions、Web。GitHubのrequired CIを通し、PR経由でリリースする。
