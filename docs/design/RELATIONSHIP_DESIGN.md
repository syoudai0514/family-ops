# 夫婦関係の設計原則（2026-11-16）

おうちノートの目的は「家事を全部記録すること」ではなく、**2人がもめずに家を回せること**です。
このページは、本番データのレビュー（2026-11-16）で見つかった事実と、今後の実装が守る原則・文面を定めます。
実装Issueはこのページを仕様として参照します。

## 1. 事実（本番データ、直近8週間）

| 事実 | 数字 |
|---|---|
| ママの操作（アプリ・LINE返信・完了記録） | **0回**。ログインは連携日の9/11の1回だけ |
| ママが受け取ったLINE | 10月66通、11月前半40通。アプリ内通知180件は既読0 |
| ママ担当として計画されたタスク（4週間） | 200件。うち記録上の完了7件（すべてパパが代わりに記録） |
| パパ自身の記録 | 10/5週 93件 → 11/2週 0件。毎週150件前後が「未完了」で残る |
| お願い（依頼）機能 | 9/21以降 0件 |
| 感謝・ねぎらいを伝える導線 | なし。システムから人への連絡は全部「やること」か「残り」 |

つまり今のおうちノートは、**片方が設計し、もう片方に1日2〜3通の「あなたの担当と残り」を送り続ける装置**になっています。
返事をしない相手に催促が届き続ける状態は、関係が良くない2人には逆効果です。
記録が残らないことは「やっていない」ことを意味しませんが、画面と数字はそう読めてしまいます。

## 2. 原則

1. **記録しない自由**。記録は任意。未記録を「未完了」「残り」と呼ばない。記録しない人を催促しない。
2. **相手を監視しない**。相手の担当リスト・残り件数・実施率を、もう片方に見せない・送らない。
   見せてよいのは「自分の動きが変わること」（送迎の担当、相手からのお願い、予定）だけ。
3. **担当は合意したものだけ**。片方が決めた割り当てを、もう片方への通知の根拠にしない。
4. **システムは責めない、比べない、数えない**。個人別の件数・割合・連続日数を出さない。
5. **良い連絡を悪い連絡より多く**。届くものの大半が「ありがとう」「助かった」「決まった予定」になるようにする。
6. **返事は1タップ**。ログインも文章入力も要らない。返さなくても何も起きない。
7. **量を減らす**。迷ったら送らない。送る価値は「これが無いと困る人がいるか」で決める。

## 3. 仕様

### 3.1 静かなモード（受け取る人ごと）
- 直近7日間、その人の操作（LINE送信・ボタン・アプリでの記録）が1回も無ければ、自動で静かなモードにする。
  1回でも操作があれば通常に戻る。本人が設定で固定もできる（「静かに」「ふつう」）。
- 静かなモードで送るもの：朝1通だけ。中身は ①今日の送り迎えが誰か ②⭐今日だけの特別な予定 ③相手からのお願い。
  何も無い日は送らない。日曜は来週の送り迎えと予定。
- 静かなモードで送らないもの：担当タスクの一覧、朝の残り、夜のノート、コドモンのリマインド、余裕があれば。

朝の文面（静かなモード）:
```
おはようございます。今日は
・送り パパ ／ 迎え ママ
・14:00 将生のプール
```
担当や予定が相手と入れ替わった日だけ、最後に1行足す: `※迎えが変わりました（パパ→ママ）`

### 3.2 相手の表示をやめる
- LINEの「相手の担当で確認したいこと」を削除する。
- 「今日」画面の「相手の今日」は、自分に関係する送迎・お願い・予定だけにし、「担当している残りN件」を削除する。
- 履歴は「家のこととして何が済んだか」を出す。人別の集計・絞り込みの初期値は「全員」。

### 3.3 未記録の扱い
- 日付が変わったら、記録の無い日課タスクは「未記録」として静かに閉じる（未完了として翌日以降に持ち越さない・数えない）。
  例外は期限が意味を持つもの（⭐特別な予定、お願い、買い物）。
- 夜のノートから「朝の残り」「日中の残り」を外す。夜は夜のことだけ。
- 「朝の残り」（7:30）は、その週に1回でも記録した人にだけ送る。「誰でもOK」のタスクは2人同時に送らない（先に家を出る人が決まっていればその人だけ、決まっていなければ送らない）。

### 3.4 担当の合意
- くり返しタスクの担当に「2人で決めた／仮」の区別を持つ。「仮」の担当は、相手側の通知に載せない。
- 合意のしかたは1タップ: 相手に `この担当でいい？ [いいよ] [変えたい] [あとで]` を1件ずつではなく、**週1回・最大3件**まで。
  「変えたい」は責めない文面で相手に届く: `「お風呂」の担当を相談したいそうです。` 理由は聞かない。
- 4週間1回も記録されていないタスクは、設定画面で「やめる／余裕があれば、に下げる／そのまま」を選べるように提案する（提案は設計した本人にだけ）。

### 3.5 ありがとう
- 相手が、自分の担当を代わりにやった時・お願いを引き受けた時・送迎を代わった時に、
  自分側に `ママがお迎えを代わってくれました [ありがとうを送る]` を出す。押すと相手に `パパから：お迎え、ありがとう。` が届く。
- 文面はシステムが作らない気持ちを足さない（既存の gemini.ts の方針と同じ）。定型は「◯◯、ありがとう。」のみ。ひとこと追記は任意。
- ありがとうは件数に数えない・履歴で集計しない。

### 3.6 言葉づかい
| 使わない | 使う |
|---|---|
| 朝の残り／未完了／残りN件 | まだのもの（本人にだけ）／未記録 |
| 相手の担当で確認したいこと | （出さない） |
| 忘れずに | 今日だけの予定 |
| できなかった | 今日はなし |
| 入力がそろっていません | あと◯◯だけ |

## 4. 測るもの（設計した本人だけが見る。相手には見せない）
- 2人とも操作があった日数／週
- 届いた連絡のうち「お願い・ありがとう・予定」の割合
- 1人あたりのLINE通数／週（目標：静かなモードで週7通以下）
人別の家事件数は指標にしない。

## 5. やらないこと
- ランキング、ポイント、連続記録、家事分担のグラフ
- 相手が既読かどうかの表示
- 未記録の人への「記録してください」という連絡

## 6. 相手を招く時（最初の1週間）

2026-11-17 時点で、ママ側は未利用（操作0回）。今の参加手順は「アカウント作成 → 招待コード入力 → 表示名」で、
入った瞬間に、相手が決めた自分の担当と未記録の一覧が並ぶ。これは招待ではなく通告として読まれる。

### 6.1 入口はLINEだけ
- 招待はLINEの友だち追加リンク1本。アカウント作成・パスワード・招待コード入力を求めない
  （連携トークン付きリンクを招く側が自分のLINEから転送する）。アプリのログインは、本人が画面を使いたくなった時に初めて案内する。
- 最初に届くメッセージは、招く側が自分の言葉で書いた1通（必須入力、定型文なし）。システムの説明はその後に3行だけ:
```
おうちノートです。
・毎朝、今日の送り迎えと予定だけお知らせします
・やめたい時は「止めて」と送ってください
```
- 招く前に、招く側の画面で「相手に最初に届くもの」をそのまま見せて確認させる。

### 6.2 最初の1週間は「知らせる」だけ
- 届くのは朝の1通（送り迎え・その日だけの予定）と、相手からのお願い・ありがとうだけ。担当タスクは一切出さない。
- 1週間後に1回だけ聞く: `家のことの分担も、ここで見られるようにしますか？ [見てみる] [今のままでいい]`
  「今のままでいい」ならそれ以上聞かない（設定からいつでも変えられる）。
- 「見てみる」を選んだら、担当は §3.4 の合意（週1回・最大3件）で1つずつ決める。相手が決めた割り当てを一括で受け入れさせない。

### 6.3 招く前に片付けておくこと（招く側）
- 記録の無いタスクが山になっていない（§3.3）。
- 相手の名前で「仮」の担当が通知に載っていない（§3.4）。
- テスト・試行で作ったお願いや予定が相手側に残っていない。

## 7. 当番という単位

この家のルールは「送りの人が朝のこと、迎えの人が夜のこと」。朝は12件前後、夜は11件前後が、その日の送迎担当にまとめて付く。
実際の記録も、夜の5〜11件を一度にまとめて完了にしている。つまり単位は個々のタスクではなく「朝当番」「夜当番」。

- LINEと「今日」画面は、当番を1行で出す: `夜の当番（お迎え〜寝かしつけまで）` 。中身は開いた時だけ。
- 記録は当番ごとに1タップ（「夜の当番、済み」）。できなかったものだけ個別に外す。
- 送迎の担当が変われば当番ごと移る。お願いも当番単位で出せる: `木曜の夜の当番を代わってほしい`。
- 相手に見せるのは「今日の夜の当番は誰か」だけ。中の11件の出来・不出来は見せない（§3.2）。
- 当番に入らないもの（その日だけの予定、ゴミ出し、誰でもOK）は今まで通り個別。

## 8. 前日のフォロー

今は毎朝「昨日：まだ完了が記録されていません」と最大8件＋ほかN件を2人それぞれに送っている。
- §3.3 のとおり未記録は責めない。前日のフォローは、その週に記録している人にだけ、1行で:
  `昨日の分、まとめて済みにしますか？ [ぜんぶ済み] [そのまま]`
- 一覧は出さない。「そのまま」や無反応なら未記録で閉じる。
