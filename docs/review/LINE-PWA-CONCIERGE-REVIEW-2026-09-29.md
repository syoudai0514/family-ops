## 0. 一番大きな問題: 誰も「完了」を記録できていない

本番の記録を見ると、**完了がほぼ一度も記録されていません。**

| 観察 | 実データ |
|---|---|
| コドモン送信タスク | 9/17〜9/29 の9日間、**全て未完了（todo）のまま** |
| 夜のブリーフ | 「朝 0/3 完了」「相手 完了 0件」 |
| 9/25 09:07 | ママが「送りました!」とLINEで返信 → **完了にならず、下書きのまま放置** |

実際にはやっているのに、アプリ上は「全部残っている」ことになっています。その結果、毎日のブリーフは**終わった作業の一覧**になり、読む価値が下がっていきます。

これが、下の問題のほとんどの根っこです。

## 1. 通知ルールの変更（実装済み）

| ご指示 | 実装 |

| （付随）祝日 | ★**本番の祝日データが0件**でした。CIのテストだけが祝日を入れていたため、9/21〜23 が平日扱い。2026〜2027年の祝日を投入 |

## 2. LINE文面の精査

### 2-1. 特殊作業の通知はわかりやすく、作業漏れが無くなるか → **いいえ**

実際に 9/29 朝ママに届いた本文（抜粋）:

```
朝やること
・将生：コドモン入力（…）  ・詩乃：コドモン入力（…） ×3
夜にやること
・お迎え ・夕食対応 ・お風呂 ・スマイルゼミ ・…（全11行）
相手の今日
・残り 9件・待ち 0件・完了 0件
・子供の着替え準備 ・朝ごはん ・…
・将生：体操着の準備・着替え    ← 特殊な準備が、相手の一覧の5番目に埋もれている
```

- **いつもと違う準備（体操着、プール、提出物）が、毎日の家事と同じ見た目で並んでいます。** 目立つ場所がありません。
- 朝に夜の家事11件まで並ぶので、本当に今日だけ気をつけることが埋もれます。
- ★相手の件数表示（残り・待ち・完了）と相手の全タスク一覧 → **削除しました**（最大3件＋「ほか N件」）
- ★同じ引き継ぎ（【言語通級】）が**2週間、毎朝毎晩くり返し**送られ、書いた本人にも届いていた → **本人には出さない・24時間で消える**ように
- ★夜8時半に、相手の**朝7時の作業**（朝ごはん・送り）や**9:15で締め切りが過ぎたコドモン入力**が「残り」として並ぶ → **夜は出さない**ように

**残っている提案**: 冒頭に「⭐ 今日だけ（いつもと違う準備）」の枠を作り、特殊作業をそこに集める。どのタスクが「特殊」かの判定（毎日ではない、保育園由来、など）を決める必要があるので、未実装です。

### 2-2. 作業完了をリンクなどから辿りやすいか → **いいえ（修正済み）**

- 9/4 の新方式切り替え以降、**ブリーフとコドモン通知は文字だけ**で、リンクもボタンもありませんでした。旧方式にはチェックインのリンクと完了ボタンがあり、それが失われていました。
- ★末尾に「▶ 完了・詳細はここから」と Today へのリンクを付けました。
- **残り**: 旧方式のような「全部やった／大体やった」のボタン（クイックリプライ）は、まだ付いていません。

### 2-3. コメントだけで完了連絡できるか → **いいえ（仕組み上できない）**

- 「〜やった」「送りました」は、**必ず「どの作業か未確定」扱いの下書き**になります（`process-line-inbox/index.ts` で `実績にする作業` を未入力として固定で付けている）。**既存の予定タスクと照合する処理がありません。**
- そのため 9/25「送りました!」は、コドモン送信タスクを完了にせず、「送信完了」という別の実績の下書きを作って止まりました。
- ユーザーには、それが分かる案内もありません。

**対応（2026-09-30）**: `process-line-inbox/lineCompletionReport.ts`。「送りました!」「洗濯した」「やった」のような**短い完了報告だけ**を、その日の自分の未完了タスクと照合する。
- 1件に絞れたら、そのまま完了（PWAと同じ完了RPC）。返信に「取り消す」ボタン
- 「送りました」はコドモン送信と送り（保育園）が両方あるので、選ぶボタンを出す
- 「やった」だけは推測せず、直近の期限の作業から選ばせる
- 今日のタスクに無い内容（「牛乳買った」）は従来どおりの流れ
- コドモンの入力が未完了なら、完了にできない理由を返す（以前はボタンを押しても無言だった）

**当初の提案**: 完了報告らしい文を受けたら、**今日の自分のタスクから候補を探して照合**する。
- 1件に絞れたら「コドモン送信を完了にしました [取り消す]」
- 複数なら「どれを完了にしますか？ [コドモン送信] [送り]」
- 直前に届いた通知（コドモン通知への返信など）を最優先の候補にする

### 2-4. 一部だけやった場合 → **LINEでは未対応**

- サブタスク（例：洗濯＝回す・干す・たたむ）の部分完了は、PWAのチェックイン画面でのみ可能です。
- LINEで「洗濯は干した、たたむのはまだ」は、上記 2-3 と同じく照合されません。
- 部分完了時に相手へ通知が行くかは、設計上「通常の家事の完了は通知しない」です（相手に負担が減るものだけ翌朝に中立表示）。

### 2-5. 作業追加は正しく動作するか → **一部失敗**

| 実際の入力 | 結果 |
|---|---|
| バナナ、リンゴジュース、ブドウジュース、角ウイスキー／自分 | ✅ 買い物4件 |
| 明日の夜にゴミ出しをする | ✅ |
| **月曜に朝プールの用意が必要なので、お願いしますね。** | ❌ **解析失敗**・期限切れで消えた |
| **買い物きている。なに変えば良い?** | ❌ 質問なのに「買い物中」という実績の下書きになった |
| **パパか担当決まっていない買い物必要なもの出して** | ❌ 質問なのに「買い物リストの作成依頼」という共有の下書きになった |
| 9/14のお迎えお願い（同日に13回） | △ 取り消し・やり直しが多発 |

- **「店にいる、何を買えばいい？」は、このアプリで最も価値のある質問の1つ**ですが、答えられていません。買い物リストを返すだけで解決します。
- 特殊な準備の依頼（プール）が失敗しているのは、2-1 の問題と重なります。

### 2-6. 長文・分かりづらい文書でも正しく判定されるか

- 花火大会の長文（「今日19時から花火大会だから、17時に詩乃を迎えにいく…」）は1件のタスクにまとまりました。
- 上表のとおり、**質問を作業として登録しようとする誤り**が残っています。ここは「登録を必ず確認してから」なので実害は出ていませんが、毎回キャンセルの手間が発生しています。

### 2-7. 保育園の写真だけで、すだち組の内容を予定に入れられるか → **いいえ**

| 本番の記録 | |
|---|---|
| 写真の取り込み | **2回試して2回とも失敗**（9/13「普通の写真」扱い、9/25 処理失敗） |
| 子ども・園・クラスの登録（`child_school_contexts`） | **0件**。すだち組が登録されていないので、読み取れても結び付け先がない |
| 失敗理由 | Edge Function のログにしか残らず、保存期間を過ぎて確認不可 |

- 取り込みは、AIが返した項目のうち**1つでも形式が合わないと全体が失敗**する作りです。
- 失敗したとき、ユーザーに何が起きたかを伝える仕組みが見当たりません。

**提案**: ①子ども・園・クラス（将生／詩乃、すだち組）を登録する画面 ②項目単位で失敗させ、読めた分は残す ③失敗理由を保存する ④失敗したらLINEで「読み取れませんでした。もう一度撮るか、文字で送ってください」と返す

## 3. PWA

前回までの修正（Today・履歴・買い物・設定）は反映済みです。残る大きな点:

- **完了の記録が面倒だから、誰も記録していない**（§0）。Today の完了は1タップですが、LINEから辿れず（§2-2 で改善）、LINEで一言では完了できない（§2-3）。
- 保育園の取り込み・子ども/クラスの設定が、事実上使えない状態（§2-7）。
- 設定の物置化、初期設定8ステップのゲートは前回の指摘のまま。

## 4. おうちコンシェルジュ

| 項目 | LINE | コンシェルジュ | 共通化 |
|---|---|---|---|
| 複数の内容を1文から分解 | ✅ | ✅ | ✅ 同じ分解処理を共用 |
| 予定の質問（今日・明日・今週） | ✅ 答える | △ 画面へ誘導するだけ | 判定は共用 |
| 相談（「どう言えば角立たない？」） | ✅ | ❌ なし | ❌ |
| 直前の内容の修正（「さっきの時間だけ変えて」） | ✅ | ❌ なし | ❌ |
| 既存タスクの完了報告 | ❌ | ❌ | — |
| 写真の取り込み | △（§2-7） | ❌ 入口なし | ❌ |

- 分解の中身は共通化できています。**会話としての機能（相談・修正・質問への回答）はLINE専用**で、PWAにはありません。
- ★質問をすると「登録する内容はありません／業務オブジェクトは作りません」と返す画面 → 文言を直しました。

## 5. 優先順位（提案）

1. **一言で完了できるようにする**（§2-3）— すべてのブリーフの価値がこれで決まる
2. **「⭐ 今日だけ」の枠**（§2-1）— 作業漏れ防止の本題
3. **「何を買えばいい？」に買い物リストで答える**（§2-5）
4. **保育園の取り込みを使える状態に**（§2-7）— まず子ども・クラスの登録から
5. ブリーフにクイックリプライ（全部やった／大体やった）を戻す（§2-2）
