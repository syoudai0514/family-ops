# 2026-10-11 Family Ops release review

対象は `syoudai0514/family-ops` の main と PR #173。Accepted ADR、Requirements Baseline、CURRENT design を基準に、画面、認証、Supabase の権限・履歴、LINE、Google Calendar、CI と復元手順を確認した。

## 修正した不具合

- 定例停止・再開で過去に外した曜日が復活する。停止は定義を停止し、現在の曜日・担当・時刻を保持する。
- LINE の確認セッションや履歴から参照されている未着手タスクの削除が外部キー制約で失敗する。参照・記録を保持して取り消し、停止からの再開では同じ回を復元する。
- 定例の複数段階の保存途中で通信に失敗すると、新規定義やチェック項目を重複作成する。保存済み段階と操作IDを保持し、同じ内容で続きから再試行する。
- 定例の名前・チェックだけを編集しても、今日以降の既存タスクへ反映されない。未着手の同じタスク・チェックIDへ反映し、完了・途中のチェック・取得済み担当・個別編集を保持する。
- 世帯・ユーザー変更後に古い定例保存の続きが新しいセッションで実行される。保存計画を世帯・ユーザー別にし、画面が閉じた後の後続コマンドを止める。確定した拒否からは最新一覧を確認して編集し直せる。
- 定例チェック編集とチェック完了のロック順が逆で、同時操作がデッドロックする。親タスクからチェックへロックする順序を統一する。
- 自動生成が有効状態を読み取った直後に定例を停止すると、停止後に未着手の回が作成される。定義編集と自動生成を同じ定義行のロックで直列化する。
- 認証初期読み込みの遅れが、新しいログイン・ログアウトを上書きする。認証イベント後の古い結果を無視する。
- 同じタブでユーザー・家庭を切り替えると、作成途中のタイトル・メモ・添付などが引き継がれる。保存した下書きとフォームの状態をユーザー・家庭ごとに分ける。
- sessionStorage が利用できないとサインインの戻り先処理が失敗する。利用可能な範囲でメモリーに保持し、サインインを妨げない。
- LINE のお願い下書きの読み込み前にフォームが初期化され、タイトル・文面・期限が空になる。該当する下書きの取得後にフォームを開く。
- LINE の予定問い合わせで、明示した年を今年へ書き換える。明示年と年を指定しない月日の問い合わせを区別する。
- Google Calendar の終了時刻のみの変更を、タイムアウトや412からの照合時に「反映済み」と判定する。開始・終了をともに照合し、日時の表記差は同一時刻として比較する。
- Google の429・5xxなど一時的な書き込み失敗を恒久失敗として保存する。同じ操作IDで再試行可能にする。
- 同一Google予定の複数回の更新が、操作台帳の接続・予定IDの一意制約に拒否される。操作IDによる冪等性を保持し、予定IDの索引を非一意にする。
- 復元時に取り消し済みの過去の実施者を現在の実施者と一致させようとして失敗する。過去の記録を保持し、現在の有効な記録と再有効化時の一致は引き続き検証する。
- 復元した過去のタスクを新規作成として再分類・再割り当てし、履歴の担当・revision・時刻を上書きする。空の復元先に限り、3つの純導出triggerを同じtransaction内で抑止して必ず復帰する。FK・check・identity・compatibility guardsと全source fieldの厳密照合は維持し、全public trigger状態の一致も検証する。
- 既に削除された適用ワークフローを呼び出す `Kick LINE UX v5` がmainのCI成功後に毎回失敗する。古いワークフローを削除する（Issue #51）。
- 手動の復元訓練が指定したブランチを無視してmainを検証する。実行対象のコミットをcheckoutする。

## リリース手順

1. 修正を含むPRの保護対象CIと実バックアップ・使い捨て環境の復元訓練を通す。
2. 本番 `dnlqxjpjpkxnfgculzip` に未適用の5マイグレーションを順に適用し、関数・権限・状態を確認する。本番リセットや履歴の削除は行わない。
3. `set-routine-definition-options`、`create-calendar-event`、`update-calendar-event`、`process-line-inbox` を同じ検証済みコミットからデプロイする。
4. PRをmainへマージし、Vercel `family-ops-web` の本番デプロイがマージコミットを参照してREADYになることを確認する。
5. 公開ページ・認証入口・PWA資産とデプロイ後の稼働状態を確認し、GitHub Releaseに結果を記録する。

## 検証の境界

Web、Edge、SQL、実Supabase CLIスタック、スマホ幅の実Chrome、バックアップと使い捨て環境への復元を検証対象とする。実家族のLINEへ検証メッセージは送らない。実iPhone・Android端末と2アカウントによる全製品F2受け入れは、今回の自動検証をもってPASSとはしない（Issues #13 / #96）。

古いPR #72、#118、#138、#46はmainに対応実装または後続実装が存在する。PR #125のacceptance-intent変更はmainに未統合であり、今回の定例編集・不具合修正のリリースへ一括マージしない。

本番のGoogle Auth providerは有効。公開されたpublic/storageテーブルのSELECT権限を調べ、RLSなしでanon/authenticatedへ公開されたテーブルは検出しなかった。Supabase Advisorsのprivate内部テーブルの「RLSポリシーなし」と、認証ユーザー向けに意図した読み取り関数のSECURITY DEFINER警告は、権限・auth.uid()・世帯制約を確認して評価する。これらの診断だけを理由に内部データを公開するポリシーは追加しない。

既存の運用改善項目として、email Authの漏えいパスワード保護が無効であること、`btree_gist`・`pg_net` がpublic schemaにあることは残る。Googleログインと世帯RLSの検証結果とは別に管理する。

## ローカル検証

- Web: 92ファイル / 336テスト、型チェック、lint、production build成功。lintの既存警告は残る。
- Edge: Deno 539テストと5つのHTTPシナリオ、全100エントリーポイントの型チェック、lint成功。Google APIの応答・タイムアウトを実handlerへ渡す回帰を含む。
- SQL: 242マイグレーションからの構築、134 assertion SQL files、別Postgres接続による並列12ケース成功。修正前のコードでデッドロック・停止後の誤生成・大文字UUID一括更新の競合が再現し、修正後に通過することを確認。
- 復元: 実snapshotの50テーブル・タスク1213件・チェック1206件を、全source field一致でlocal scratchへ復元。FK・check・actor・compatibility拒否時のtransaction rollbackとtrigger復帰も検証。
- 実Chromeスマホ幅: CF-14の6シナリオとToday/navigationの4シナリオ成功。
- npm production依存監査: 脆弱性0件。
- 本番権限監査: 世帯RLS、業務テーブル直接書込禁止、private schema非公開、関数実行権限を確認。

実Supabase CLIスタック、コミットに紐づく実Chrome証跡、実バックアップからの認証ユーザー再作成を伴う復元結果は、PRのGitHub ActionsおよびGitHub Releaseに記録する。
