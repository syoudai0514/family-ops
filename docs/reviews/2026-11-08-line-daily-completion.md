# Issue #193: LINEの日常操作の継続

複数のお願いから対象を選び、返答・相談・期限変更をLINE内で続けられるようにした。送信前カードの編集と通常依頼の「その他の返答」もトーク内へ接続した。コメント付き辞退は既存の状態遷移と同じ通知にまとめ、同じ確認ボタンの再送は同じ結果を参照する。

入力は対象日と朝/夜の範囲を示し、今日・昨日の個別記録・訂正へ切り替えられる。全体完了の取り消しと、チェックリストの項目単位の訂正を分けた。新しい日常完了/失敗訂正のアダプターは日付・世帯・対象との関係・revisionをDBロック内で確認し、既存の正規コマンドを呼ぶ。コドモンは明示した「送信した」操作で従来の送信確認を使う。

最近24時間の本人のLINE登録結果から、対応する通常の単発作業だけを日時訂正できる。保存結果ID・本人・世帯・現在のrevisionを照合し、予定の長さ・担当・カレンダー設定を保持する。定例・送迎・依頼に紐付く作業・複雑な日またぎ変更はこの簡易訂正の対象に含めない。

予定の続きを6件ずつLINEで表示し、元の照会日/期間と現在のactorを保持する。自然文の部分報告は、既存チェック項目または途中状況の記録へ接続した。AIの参照と原発言を照合し、部分処理が再送時に従来の全体完了へ流れないようにした。途中記録だけで共有や依頼を送らない。

## 検証

- Edge: 全707テスト・94 HTTP steps、lint、全91入口の型検査、認証matrixが成功。実worker入口からカード編集・保存済み訂正・予定ページ・部分記録の後続操作まで、外部通信を捕捉した架空データで確認した。
- DB: PostgreSQL 16.11の使い捨てローカルDBへ全261 migrationを適用。全150 SQL assertion filesと既存の実並列concurrency suiteが成功。新規SQLは別世帯・別actor・日付/版の不一致・期限切れ・同じ操作の再送・変えたpayloadの拒否・コドモン実施者を確認する。
- Web: lint（既存warningあり）、型検査、全102ファイル/414テスト、production buildが成功。
- 既存SQL70の週単位の日付移動が祝日に当たる問題と、SQL109の全家庭workerに別テストの通知設定が混ざる問題を修正。製品の祝日判定・通知ルールは変更していない。

## 反映と残る確認

追加した3 migrationを先に適用し、その後に同じリビジョンの `process-line-inbox` と `send-notifications` を反映する。新しいEdge endpointは増やしていない。本変更は実装と自動検証までで、本番反映や実家庭のデータ変更・LINE試験送信は行っていない。異なる2つの実LINE identityとスマートフォンでの操作確認は未実施であり、自動テストの成功をその代わりにしない。
